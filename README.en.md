# ssh_krb_check

**English** | [Русский](README.md)

Check whether hosts accept SSH logins with a Kerberos ticket (GSSAPI / gssapi-with-mic), no password. Two modes: a NetExec (nxc) module and a standalone CLI.

Each target is probed over a separate ssh connection that allows `gssapi-with-mic` only (keys, passwords, ssh-agent and ControlMaster reuse are disabled) — a success is guaranteed to come from the ticket.

## Requirements

- a Kerberos ticket (`kinit`), the `KRB5_CONFIG` and `KRB5CCNAME` variables
- `ssh`, `klist` in PATH
- Python 3 (stdlib only); NetExec for the module mode

## Installation

```bash
cp ssh_krb_check.py ~/.nxc/modules/
```

## Kerberos environment

```bash
export KRB5CCNAME=/path/to/krb5cc          # ticket cache
export KRB5_CONFIG=/path/to/krb5.conf      # config with the KDC address

# krb5.conf can be generated by nxc itself:
nxc smb <ip> -u <user> -p <pass> --generate-krb5-file krb5.conf
```

Without `KRB5_CONFIG`, checks succeed only for targets whose service ticket is already present in the cache; new targets time out (KDC lookup via DNS).

## nxc module: usage variants

Ticket only, no credentials at all (the user is taken from the ticket):

```bash
nxc ssh 10.10.10.1-50 -M ssh_krb_check
```

Custom port:

```bash
nxc ssh 10.10.10.5 --port 2222 -M ssh_krb_check
```

Execution flags — combined with `-M` (the stock nxc ssh protocol ignores them next to `-M`); they work both with password/key and with no credentials:

```bash
nxc ssh 10.10.10.5 -M ssh_krb_check -x 'id'                            # run a command
nxc ssh 10.10.10.5 -M ssh_krb_check --put-file file.txt /tmp/file.txt  # upload a file
nxc ssh 10.10.10.5 -M ssh_krb_check --get-file /etc/hosts hosts.txt    # download a file
nxc ssh 10.10.10.5 -M ssh_krb_check -x 'id' --put-file a.txt /tmp/a.txt --get-file /tmp/b.txt b.txt
```

Without credentials, commands and file transfers go through the ticket (system `ssh`/`scp`); with a password/key — stock nxc mechanisms (paramiko/SFTP).

Module options (`-o KEY=VALUE`, several allowed):

| Option | Default | Description |
|---|---|---|
| `TIMEOUT` | `8` | connection timeout, sec |
| `DELEGATE` | `FALSE` | delegate the ticket to the host (`ssh -K`) |
| `VERBOSE` | `FALSE` | full ssh output on failure |

```bash
nxc ssh hosts.txt -M ssh_krb_check -o TIMEOUT=5 DELEGATE=true
```

User: `-u` from nxc, otherwise the ticket principal. Port: `--port` from nxc.

Output:

```
SSH            10.111.222.11   22   [+] testuser: (kerberos ticket) Linux - Shell access!
SSH_KRB_CHECK  10.111.222.13   22   [-] ssh_krb_check: аутентификация по Kerberos НЕ прошла (Permission denied ...)
```

## Standalone CLI: usage variants

IPs, names, full ranges (`10.10.10.1-10.10.10.50`) and short ones (`10.10.10.1-50`):

```bash
python3 ssh_krb_check.py 10.10.10.1 10.10.10.5-10.10.10.20 srv01.corp.local
python3 ssh_krb_check.py 10.10.10.1-50
```

Host file, parallelism, OK-list export:

```bash
python3 ssh_krb_check.py -f hosts.txt -P 20 -t 5 -o ok_hosts.txt
```

Custom user and port, a command after login, error details:

```bash
python3 ssh_krb_check.py -u admin -p 2222 -c 'id' -v srv01.corp.local
```

Ticket delegation (equivalent of `ssh -K`):

```bash
python3 ssh_krb_check.py -K 10.10.10.5
python3 ssh_krb_check.py -l 10.10.10.1-50
```

Flags:

| Flag | Default | Description |
|---|---|---|
| `-u` | ticket principal, else current user | SSH user |
| `-p` | `22` | SSH port |
| `-t` | `8` | timeout, sec |
| `-c` | `true` | command to run after login |
| `-K` | off | delegate the ticket (`ssh -K`) |
| `-P` | `10` | parallel checks |
| `-f` | — | host file (`#` — comment) |
| `-o` | — | file for the OK-host list |
| `-l` | — | print the host list after expanding ranges, no connections |
| `-v` | — | full ssh output on failure |

Statuses: `OK` — ticket login succeeded; `FAIL` — authentication failed; `UNREACH` — host unreachable. Exit codes: `0` — all OK, `1` — FAIL/UNREACH present, `2` — argument error.

## Limitations

- for IP targets the service principal `host/<fqdn>` is resolved via krb5 reverse DNS; FQDN targets are preferred
- every check is a login attempt in the target's sshd log
- `--sudo-check` without credentials does not copy `/etc/shadow` (the stock scenario requires a password) — NOPASSWD probe only
